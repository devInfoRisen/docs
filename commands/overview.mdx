Nexa gives your customers a direct line to their orders through the messaging apps they already use. Instead of contacting support manually, a verified customer can type a short plain-text command into the Nexa bot conversation on WhatsApp or Telegram, and Nexa handles the rest — checking ownership, contacting the provider where needed, and replying with a clear confirmation or explanation.

## Available Commands

The table below lists every command Nexa currently recognises, along with a quick example and a description of what happens when the command is processed.

| Command | Example | What happens |
|---|---|---|
| `refill order <ID>` | `refill order 5381` | Verifies ownership of a completed order and notifies the provider to trigger a refill. |
| `partial order <ID>` | `partial order 5381` | Returns an estimate of how much of the order has been delivered so far. No action is taken with the provider (MVP). |
| `speed up <ID>` | `speed up 5381` | Notifies the provider to accelerate an active order, or returns a delivery estimate if the order is partial. |
| `cancel order <ID>` | `cancel order 5381` | *(Coming soon)* Submits a cancellation request to Perfect Panel after verifying ownership. |

## Ownership Verification

Every command goes through Nexa's ownership check before anything happens. Nexa cross-references the sender's WhatsApp or Telegram number against a verified Perfect Panel username, then confirms that the order ID belongs to that same username. If either check fails — unrecognised number, unverified account, or order belonging to a different user — Nexa denies the command and replies with an explanation. Nexa never acts on a mismatch.

## Case-Insensitive Commands

Commands are case-insensitive. `Refill Order 5381`, `REFILL ORDER 5381`, and `refill order 5381` are all treated identically. Customers don't need to worry about capitalisation.
